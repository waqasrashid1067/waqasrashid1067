## Agentic Architecture

The through-line in most of my work: how do you take a plain-language request and turn it into a correct sequence of tool calls, without the agent wandering off or costing a fortune?

**Agent creation & tool orchestration**
Agents built from a `tools / skills / connectors` registry so capabilities are registered rather than hard-coded — a planner reads the request, decides whether it needs one tool or a chain of them, and executes. Multi-agent setups where a conversational agent, an analytical agent, a content agent and a RAG agent share one workspace and hand off between each other.

**Reasoning loops & autonomous execution**
Plan → act → observe → re-plan, with retries and error handling at each hop, so a failed tool call becomes a recovery step instead of a dead end.

**MCP connectors**
Custom MCP servers exposing tools to an LLM client, plus integrating existing connectors (monday.com, Apollo, Notion, Canva, Apify, Git/GitHub, filesystem) as the agent's action surface.

**Multi-provider LLM routing**
A provider layer over Groq, Gemini, Cerebras and OpenRouter with fallback, so a rate limit or a dead endpoint doesn't take the agent down — with every request and response logged to Redis so failures stay debuggable after the fact.

**Memory management — three-tier design**
Working context in Redis · thread and cross-conversation memory in PostgreSQL/pgvector · hybrid retrieval with dedupe-and-merge, metadata filtering, and background fact extraction on Celery/RQ. Keeps an agent coherent across sessions without stuffing the context window.

**Guardrails**
Topic-scoping so the harness can't be talked off-task, confirmation gates before any paid tool runs, no re-spending credits on already-fetched data, and explicit refusal behaviour when the answer isn't in the retrieved context.
